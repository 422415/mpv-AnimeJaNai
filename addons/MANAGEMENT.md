# Trusted management protocol 1.2 preview

This protocol connects AJN Manager to the persistent host. It is **not** an addon capability. Guests only receive their private broker channel and cannot install packages, edit grants, or control another addon through it.

Run `ajn-addon.exe serve <data-directory> <wasmtime.exe>`. Manager can launch this executable from `<AJN root>/addon-host` without opening a console. Package the self-contained host there and the verified runtime at `addon-host/runtime/wasmtime.exe`. The canonical C# client is `sdk/csharp/ManagementClient.cs`; the companion Manager repository includes an identical copy without a cross-repository project dependency.

The service is on demand, per Windows user and data directory. It holds `host.lock` exclusively, permits eight clients, and exits after about 30 seconds without connected clients or running workers. No Windows service, login task, TCP port, or automatic startup entry is installed. Background manual activations deliberately keep it running after Manager closes.

## Connection and limits

The pipe name is `AJN.Addons.v1.` followed by the first 32 lowercase hexadecimal characters of SHA256 over the UTF-8, uppercase, full data-directory path with its trailing directory separator removed. Protocol 1's Windows path normalization is platform-specific; a Linux transport will use the same message semantics with its own endpoint discovery.

The first listener uses `FirstPipeInstance`. Its protected ACL grants its Windows owner full control and denies NETWORK logons. The client uses `CurrentUserOnly`; this follows Windows owner/elevation semantics. The ACL is installed atomically at pipe creation. The restricted token used by some development sandboxes may prevent connecting even when their interactive user is the same; test with a normal same-user process rather than weakening the ACL.

Messages use the guest protocol's bounded JSON-RPC profile: UTF-8 JSON objects, 128 KiB, depth 24, no batches/notifications, unique object keys. Calls have a 30-second service deadline and a 35-second client deadline. The first call must be `manager.hello` with `{ "major": 1 }`; the response includes major/minor versions. Connection identities are generated by the service.

| Method | Parameters | Behavior |
| --- | --- | --- |
| `manager.hello` | `{major:1}` | Register this connection; acquire declared `on_manager` activations |
| `addons.list` | `{after?:string}` | Up to 16 summaries and `nextCursor`; client helper joins all pages |
| `addons.inspect` | `{path}` | Validated manifest and exact package `hash`; no installation |
| `addons.installDev` | `{path,expectedHash,permissions}` | Revalidate the reviewed hash and selected grant, replace registration, activate for connected Managers |
| `addons.start` | `{id}` | Explicit manual activation; retries a previously stopped worker |
| `addons.stop` | `{id}` | Release all current activation reasons and stop the worker |
| `addons.remove` | `{id}` | Stop and unregister; retain private data/settings for recovery |
| `addons.rollback` | `{id}` | Verify the previous package before stopping; restore its code/grant |
| `addons.settings` | `{id}` | Definitions, editable values, `invalidSettings` keys, declared actions |
| `addons.configure` | `{id,changes}` | Validate and atomically save settings; notify a running worker |
| `addons.action` | `{id,action}` | Run a declared action, sharing an existing worker or starting temporarily |
| `addons.logs` | `{id}` | Last 32 messages, at most 512 UTF-16 units each |
| `media.selections` | `{id}` | Approved files (with trusted-UI paths) and saved profile labels |
| `media.approveSource` | `{id,expectedHash,path}` | Approve one local file for the reviewed addon package |
| `media.approveProfile` | `{id,expectedHash,name,slot,backend,configuration}` | Save an immutable profile configuration snapshot |
| `media.revoke` | `{id,expectedHash,kind,selectionId}` | Stop and drain the addon before removing one source/profile approval |
| `network.selections` | `{id}` | Approved destinations and credential metadata, never values |
| `network.inspectDestination` | `{id,expectedHash,origin}` | Resolve and return a canonical destination plus a single-use three-minute review ID |
| `network.approveDestination` | `{id,expectedHash,reviewId,name}` | Approve the reviewed protocol, origin and pinned addresses |
| `network.setCredential` | `{id,expectedHash,destinationId,header,value}` | Validate, stop addon and protect the header for this service |
| `network.removeCredential` | `{id,expectedHash,destinationId}` | Stop/drain; remove only the saved header |
| `network.revoke` | `{id,expectedHash,destinationId}` | Stop/drain; remove destination and credential |

Management 1.2 adds `networkAvailable` and `credentialsAvailable` hello flags,
and `networkPermission`/`credentialPermission` summary fields. These are trusted
UI operations, distinct from guest `network.*` methods. Reviewed addresses stay
in host memory until approval; client parameters cannot replace them. See
[NETWORK.md](NETWORK.md) for the authority and credential limits.

The four media operations require a configured native provider and the addon's `sessions.manage` grant. `manager.hello` includes `nativeMediaAvailable`; addon summaries include `mediaPermission`. The standalone client exposes a copy of the hello result in `ServerInfo`. Resource consent uses the currently reviewed addon hash, so changing the installed version while a dialog is open causes rejection. See [NATIVE-MEDIA.md](NATIVE-MEDIA.md) for provider setup and resource limits.

The registry supports 128 installed addons; the worker limit is eight. A failed package lookup does not permanently consume a host entry. One corrupt addon gets its own error row and can still be removed. An invalid rollback request leaves its running worker alone. An install validates the selected package and grant before stopping the previous instance; an I/O failure during the subsequent atomic registration may require explicitly restarting the still-registered old package.

On disconnection, only that connection's `on_manager` reason is released. Other Manager connections and explicit manual starts keep their activation. Stop does not unregister the package; a new relevant activation may start it later. Remove prevents future activation. There is no automatic crash/restart loop.

When a new settings schema rejects a saved value, `addons.settings` returns that field's default and identifies it in `invalidSettings`. Manager visibly explains the repair. Reading does not overwrite the original value; clicking Save validates and persists the chosen replacements. Corrupt JSON files remain preserved for manual recovery. Saving succeeds durably before notifying an addon; if the notification fails, the saved data is still retained.

## Validation

The main suite exercises real pipes, owner/network ACLs, multiple clients, background activation, pagination, bounded Unicode logs, failed lookups, corrupt registration recovery, and a real Wasmtime worker through this protocol. The companion Manager suite checks native controls, typed setting round trips, actions, lifecycle buttons, unchecked permission defaults, selected grants, and hash-bound review, and captures rendered screenshots.
